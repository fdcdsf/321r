# 321r.ru — инфраструктура на 3 VPS

Отказоустойчивая система: Pangolin-кластер (доступ к сервисам), Docker Swarm (запуск
сервисов), AmneziaWG-меш (связь узлов), PostgreSQL + MongoDB (классическая репликация по
приложениям: первичного назначает db-guard по кворуму Swarm), Remnawave (VPN для обхода
цензуры), Komodo (панель управления).

- **[PLAN.md](PLAN.md)** — полный план (v14): роли узлов, фазы, сценарии отказов, порты.
- **[docs/dns.md](docs/dns.md)** — записи Cloudflare для зоны 321r.ru.

## Ключевые решения (чтобы не переоткрывать)

- Домен **321r.ru**, узлы **a/b/c** (a = РФ).
- DNS: один хаб **`dns.321r.ru`** (A ×3), всё остальное — **CNAME → dns**: при смене IP
  руками не правится ничего (ddns.sh обновляет 6 записей сама).
- Меш — **AmneziaWG** сразу; запасной путь — обычный WireGuard.
- Контрольные панели (Komodo, Remnawave) — на VPS; дом — только Newt и сервисы.
- Автовосстановление встроено там, где данные: Swarm (размещение и кворум), **db-guard**
  (назначает первичного PG и Mongo по голосам ≥2/3 + цепи, фенсит изолированную ноду),
  реплика-сет (внутренний мажоритар Mongo). Ручное — только крайние случаи.
- **БД v14 (вместо Spock)**: один инстанс = одно приложение (D1), инстансы только на узлах
  S(X) приложения; адрес — VIP `10.66.0.99:порт` (одинаков на всех нодах, env статичен
  навсегда), за ним локальный haproxy → текущий первичный. Новое приложение = запись в
  `apps.d/` + `db-add` — репликация и прокси настраиваются сами. Классы: кластерный /
  локальный (Remnawave) / служебный (арбитры).
- **Бэкапы — без R2** (2026-11-09): копии между своими VPS по mesh; GitHub — только конфиги.
- Расширение: узлы **D и E** (год бесплатно от старого хостинга) принимаются без переделки
  (3 → 5 и обратно); минимум — 3 узла.
