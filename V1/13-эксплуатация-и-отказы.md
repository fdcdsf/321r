## Сценарии отказов (что происходит само и что делать)

### A. Смена IP зарубежной ноды

- **Само:** ddns (≤2 мин) → reresolve (≤45 с) → update-pangolin-ips. Newt/агенты уходят на
  живые ноды.
- **Человек:** ничего; проверить `wg show` и https://pangolin.321r.ru/.
- Дрилл синтетический пройден 2026-11-08.

### A2. Заблокированы несколько зарубежных IP из РФ

- **Само:** вход из РФ идёт через VPS-1 (РФ, её не блокируют); изолированная нода получает
  фенс (нет кворума >60 с → DROP в DOCKER-USER): данные целы, молчит; большинство пишет.
- **Человек:** смена IP у провайдера ([07](07-замена-сервера.md), случай 2); для людей —
  VPN-слой (фаза 9) делает блокировки невидимыми.
- Оговорка: запись с изолированной ноды в период изоляции невозможна — CP-режим, осознанный.

### B. Потеря одной VPS («ракета»)

- **Само (секунды–2 мин):** Swarm переносит задачи (в т.ч. Core Komodo, Kuma); db-guard
  голосует ≥2/3 и назначает нового первичного; прокси переключаются — приложения пишут
  дальше (адрес VIP не менялся); кластер жив на N−1.
- **Человек (~1 час):** новая VPS → процедура [07-замена-сервера](07-замена-сервера.md), случай 3.
- Потеря ACME-ноды: ACME временно выключен, сертификаты живут в БД; при замене — включить
  `enable_acme_client` на одной живой ноде.

### C. Потеря ноды-первичного БД

- **Само (≤2 мин):** следующий по цепи промоутился (PG) / назначен (Mongo), прокси на всех
  нодах переключились, метки Swarm обновлены. RPO — последние секунды (async).
- **Человек:** как в B (данные догонятся репликацией); дампы — страховка от логических ошибок.
- Вернувшийся старый первичный становится стендбаем после пересборки (~1 мин) — штатно
  (`pg-rebuild-standby.sh`, если таймлайн разошёлся).

### D. Потеря двух VPS (худший случай)

- **Само:** кворума нет → страж фенсит выжившую ноду (данные целы, CP-режим).
- **Человек (часы):**
  1. На выжившей: `docker swarm force-new-cluster` → стеки из git.
  2. Снять фенс (правила DROP в DOCKER-USER, позиция 1).
  3. Данные: base+WAL с бэкап-ноды VPS-3, дампы с VPS-1 → [10-бэкапы](10-бэкапы.md).
  4. Фазы 4–5 заново по runbook; новые ноды — [05-добавление](05-добавление-ноды.md).
- Готовность подтверждается **квартальным дриллом восстановления** — без дрилла это
  теория, а не обещание.

## Правила человеческого вмешательства

1. **Сначала смотрим, само ли чинится** (2–5 мин): db-guard, Swarm, ddns, repair-cron —
   большинство инцидентов закрывает автоматика.
2. Дрилл-блоки — **одним куском из одного терминала**, первая строка проверяет ноду
   (урок инцидента 2026-11-10: команда ушла не на ту ноду).
3. Каждое действие с БД — через VIP; каждое действие с pangolin — помним про repair после.
4. После любого инцидента — фиксация: что случилось, что чинили, что автоматизировать
   (правило 4: фикс → вики + инсталлятор).
