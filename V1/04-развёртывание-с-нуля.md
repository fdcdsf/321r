## Идея одной команды

**Одна команда = запуск идемпотентного оркестратора**, который прогоняет ноду (или весь
кластер) через стадии S0–S9. Каждая стадия:
- проверяет, сделано ли уже (можно запускать повторно без вреда);
- делает шаг и оставляет проверяемый след;
- при сбое останавливается с понятным сообщением «что сломалось и как чинить».

Аналогия: сборка мебели по одной инструкции — можно прерваться на любом шаге и продолжить,
ничего не сломав.

## Точка входа A: чистая VPS → готовый узел (продукт, публичный репозиторий)

```bash
# на чистой Debian 13 (root):
curl -fsSL https://raw.githubusercontent.com/<org>/321r/master/bootstrap.sh | \
  bash -s -- --cluster 321r --token <одноразовый-токен-кластера>
```

Токен выдаёт существующий кластер (`cluster.sh token create`) и содержит: адрес координатора
(mesh-адрес ближайшей ноды), зашифрованный пакет секретов кластера (HPK меша, server.secret),
alias новой ноды и её mesh-IP. Токен одноразовый и живёт 1 час.

## Точка входа B: весь кластер с нуля (с рабочей машины админа)

```bash
# 3 пустых VPS → полный кластер за ~1 час:
bash cluster.sh up inventory.yaml
```

`inventory.yaml` — единственная входная точка конфигурации (эволюция `nodes.map`):

```yaml
cluster:
  domain: 321r.ru            # базовый домен
  email: you@example.com     # ACME-контакт
  timezone: UTC
cloudflare:
  token_ref: file:///root/.secrets/cf.token   # не в git!
nodes:
  - { alias: a, ip: 178.236.242.213, mesh: 10.66.0.1, role: state, region: ru }
  - { alias: b, ip: 48.102.162.135,  mesh: 10.66.0.2, role: work  }
  - { alias: c, ip: 194.48.141.214,  mesh: 10.66.0.3, role: bulk  }
apps:                        # реестр apps.d: кому какие БД
  - { name: pangolin, engine: pg,    placement: [a, b, c] }
  - { name: komodo,   engine: mongo, placement: [b, c], arbiter: a }
```

Оркестратор: генерирует секреты → раскатывает стадии на все ноды (параллельно, где можно) →
собирает кластер → прогоняет автопроверки → печатает итоговый отчёт «что получилось».

## Стадии (S0–S9) — они же порядок ручной установки

| Стадия | Что делает | Идемпотентность / проверка |
|---|---|---|
| **S0 Проверки** | ОС Debian 12+, `systemd-detect-virt` = kvm/none (иначе AmneziaWG не встанет!), RAM ≥ 1 GB (комфортно 2), диск, доступность IP, пинг до CF/Let's Encrypt, DNS-зона отвечает | просто докладывает; «нет» = стоп с причиной |
| **S1 ОС** | пакеты (docker, dkms, headers, curl, jq…), UTC+NTP, hostname по alias | сверка версий |
| **S2 Вход и защита** | ключи SSH → порт 2222 (сначала подтверждаем ключевой вход, потом отключаем пароль!), ufw по таблице [03-факты](03-факты.md), fail2ban | `sshd -T`, `ufw status`, матрица SSH |
| **S3 Меш** | AmneziaWG 3.1 (PPA+DKMS), wg0.conf из инвентаря (HPK — общий секрет!), VIP 10.66.0.99, `awg0-up`, `reresolve-dns.timer` | `wg show` — handshake со всеми; пинг 10.66.0.x |
| **S4 Swarm** | первая нода: `swarm init`; остальные: join МЕНЕДЖЕРАМИ (правило 2K+1); метки role=…; DOCKER-USER (docker-user.sh + systemd) | `docker node ls` = N×Ready; iptables DOCKER-USER → последний DROP |
| **S5 Слой БД** | `db-prep` (каталоги, ufw-зона контейнеров, nodes.map), `apps.d/` из инвентаря, `db-add` для системных приложений, `db-guard.timer` | запись через VIP, `pg_stat_replication`, `rs.status()` |
| **S6 Pangolin** | рендер `/opt/pangolin` из шаблонов, compose up (pangolin+gerbil+traefik вместе!), первичная инициализация, `pangolin-wildcard-repair.sh` + cron, сайт-агент `cluster-<alias>` | `https://<base>` = 200 со всех IP; сертификат SAN = `*.<base>` |
| **S7 Komodo** | Core (swarm-стек), periphery (systemd) ×N, onboarding-key, `komodo.<base>` | `komodo.<base>` = 200; все серверы онлайн |
| **S8 Мониторинг/бэкапы** | Kuma-мониторы, cron бэкапов по правилу «2 соседние» ([10-бэкапы](10-бэкапы.md)), Telegram-алерты | тест-алерт в Telegram; свежесть бэкапа |
| **S9 Верификация** | автопроверки (список ниже) → отчёт | зелёный отчёт = кластер принят |

## Автопроверки приёмки (S9)

```text
[ ] wg show — handshake со всеми пирами (включая РФ↔зарубеж)
[ ] docker node ls — все узлы Ready, роли проставлены
[ ] curl https://<base>/ = 200 со ВСЕХ IP нод (--resolve по каждому)
[ ] openssl: сертификат содержит *.<base> и <base>
[ ] тестовый ресурс test.<base> = 200 со всех IP
[ ] запись в PG через 10.66.0.99:<порт> успешна; стендбай в pg_stat_replication
[ ] rs.status(): PRIMARY + SECONDARY(+ARBITER)
[ ] journalctl -t db-guard — нет «мой инстанс не отвечает»
[ ] unhealthy-restart и wildcard-repair отработали по cron (логи есть)
[ ] nmap с соседней ноды = таблица портов 03-фактов
```

## Фабрика секретов (как не тащить секреты через чат/git)

| Секрет | Кто генерирует | Куда кладёт |
|---|---|---|
| HPK меша (один на все ноды) | оркестратор (один раз) | `/etc/amnezia/amneziawg/wg0.conf` всех нод |
| `server.secret` Pangolin (один на все ноды) | оркестратор | `/etc/db/secrets/pangolin.env` |
| Пароли PG/Mongo (свой на приложение) | **сама нода** при `db-add` (umask 077) | `/etc/db/secrets/<app>.env` |
| Ключи SSH нод | нода при первом запуске или владелец | `~/.ssh`, `authorized_keys` |
| CF-токен | владелец (вводит один раз) | `/etc/ddns.env`, `/etc/db/secrets/traefik-cf.env` |
| Komodo admin/jwt | нода | `/etc/db/secrets/komodo.env` |

Правило: **секреты генерируются на нодах и остаются на нодах**; через рабочую машину проходит
только зашифрованный одноразовый пакет.

## Ручной путь (если скриптов ещё нет) — сжатый чек-лист

Порядок — строго по стадиям S0–S9 (полные описания — в соответствующих файлах вики):

1. Проверки S0 → S2 (вход, ufw, fail2ban): [12-безопасность](12-безопасность.md).
2. Меш S3: рецепт `docs/amnezia-wg.md`; ключевое: HPK одинаковый на всех, `awg0-up`.
3. Swarm S4: init на одной, join менеджерами на остальных, DOCKER-USER.
4. БД S5: `db-prep` → `db-add` по реестру: [09-базы-данных](09-базы-данных.md).
5. Pangolin S6: шаблоны `deploy/pangolin/*.tmpl` + рецепт `docs/pangolin-wildcard.md`.
6. Komodo S7 → мониторинг/бэкапы S8 → верификация S9.
7. **Каждый шаг фиксируется в этой вики** (правило 4 из README).

## Восстановление всего кластера «ракетой» (нулевой цикл)

```bash
bash cluster.sh up inventory.yaml        # ~1 час: кластер как новый
bash cluster.sh restore --from <нода>    # данные из бэкапов: [10-бэкапы](10-бэкапы.md)
```

RTO: инфраструктура ~1 час, данные — по объёму (дампы + WAL). Это и есть квартальный
дрилл восстановления ([17-дриллы](17-дриллы.md)).

## Чего одна команда НЕ делает (границы автоматики)

- Не покупает VPS и не заводит аккаунты (фаза 0 — руками владельца, один раз).
- Не включает 2FA и не прячет recovery-коды (человеческое).
- Не вытаскивает данные из полностью сгоревшей без бэкапов ноды (бэкапы — [10](10-бэкапы.md)).
