# V1/00 · Быстрый старт для нового пользователя

Вы нашли проект **321r** — отказоустойчивую инфраструктуру на 3 VPS: общие базы
данных с автоматическим переключением, бэкапы по правилу 3-2-1, защищённый меш
между серверами и Telegram-бот как панель управления. Этот документ — всё, что
нужно, чтобы повторить у себя. Больше ничего не требуется: **установщик делает
всё сам**.

## Что понадобится

| Что | Зачем | Минимум |
|---|---|---|
| 3 сервера (VPS) | кластер правилит 2K+1: переживает потерю любого одного | **Debian 12/13 или Ubuntu 22.04/24.04/26.04** (смешивать можно — проверено), **полная виртуализация** (KVM/VMware/Hyper-V; OpenVZ/LXC не подойдут), 1 ядро / 1 ГБ (комфортно 2 ГБ) |
| Домен (по желанию) | панели, маскировка, сертификаты | любой, DNS у Cloudflare |
| Telegram-бот | панель управления и алерты | создать у @BotFather (2 минуты) |

Честные минимумы железа — в [V1/20](20-ресурсы-и-профили.md): ядро кластера
вполне живёт на 3 × (1 ядро, 1 ГБ); панели и MongoDB просят ноды побольше.

## Шаг 0 · Установка одной командой

Зайдите по ssh на **первый** сервер (от root) и выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/fdcdsf/321r/master/install/bootstrap.sh | bash
```

Это всё. Мастер-установщик спросит всё остальное и **поставит систему на все
сервера одновременно**:

- адреса остальных серверов и их root-пароли (нужны один раз, чтобы заложить
  свой ключ — дальше пароли не нужны и отключаются);
- токен Telegram-бота и chat id владельца (узнать: @userinfobot);
- домен и Cloudflare-токен (можно пусто — тогда ставится только ядро);
- Pangolin: ручная или автоматическая первичная настройка; если у вас есть EE-лицензия,
  можно ввести её скрытым вводом (пустой ввод — без лицензии);
- Remnawave: `install` — панель на control VPS, либо `connect` — панель на
  домашнем сервере за Newt через Pangolin (введите HTTPS-адрес и API-токен);
  в обоих режимах на VPS ставятся отдельные VPN-ноды и минимальная подписка;
- для обхода блокировки Telegram можно указать **отдельный файл WARP `.conf`
  на каждую VPS** (путь на первом сервере), либо загрузить его позже через бота;
- профиль ресурсов и приложения (базы данных).

Либо, если привычнее с ноутбука: `git clone`, заполнить
`install/inventory.conf` и запустить `./install/install.sh` — та же машина шагов.

## Шаг 1 · Установка (15–30 минут, можно пить чай)

Установщик проходит все шаги сам, **на всех серверах параллельно**, печатая ход дела:

1. предпроверки (виртуализация, память, ядро) и ключ межнодового доступа;
2. базовая подготовка серверов: Docker, firewall, fail2ban, лимиты логов, часы UTC;
3. меш AmneziaWG — серверы видят друг друга по внутренним адресам 10.66.0.x;
4. Docker Swarm — все серверы менеджеры (правило 2K+1);
5. слой баз данных: PostgreSQL/MongoDB с репликацией, диспетчер портов на VIP,
   `db-guard` — «мозг», который следит за здоровьем и переключает первичного;
6. бэкапы 3-2-1: каждая нода пишет копии на две другие, ночью, с проверкой
   восстановления по воскресеньям;
7. Telegram-бот: панель управления, алерты, дайджест в 09:00;
8. автоприёмка — проверяет всё по чек-листу;
9. финальная защита: парольный вход отключается, лишние порты закрываются.

Любой шаг можно перезапустить: `./install/install.sh --from=db` — установщик
идемпотентен, работающее не сломает.

**Секреты.** Токен бота и пароли не попадают в git: установщик генерирует пароли
баз сам и кладёт их только на серверы (`/etc/db/secrets/`, права 600). Введённые
вами пароли серверов используются один раз и нигде не сохраняются.

## Шаг 2 · Приёмка

В конце установки печатается отчёт автоприёмки — все строки `✓`. Проверьте руками:

- в Telegram пришло меню бота — покрутите кнопки (📊 Статус, 💾 Бэкапы, 🗄 Базы);
- **в Telegram придёт файл «🔐 Памятка владельца»** — все пароли, ключи, секреты и
  ссылки одним файлом: сохраните его в менеджере паролей или распечатайте (на
  серверах он тоже лежит: `/root/321r-pamyatka-*.txt`, права 600). Там же — код
  первичной настройки Pangolin (`setup token`): без него не пройти первый вход
  в панель;
- в режиме `install` Remnawave памятка содержит две разные ссылки:
  `https://sub.<домен>/<shortUuid>` — **страница для человека** с интерфейсом;
  `https://rem.<домен>/api/sub/<shortUuid>` — **сырая подписка** для VPN-приложения
  (в браузере она может выглядеть как технические данные);
- утром придёт дайджест, а при любой беде — алерт;
- бот показывает **всё, что есть на серверах, само**: новые базы, контейнеры,
  сервисы появляются без настроек (кнопка 🔄 Обновить).

Повторная проверка в любой момент: `./install/install.sh --check`.

## Шаг 3 · Приложения (по желанию)

Ядро кластера — это базы, бэкапы и бот. Панели поверх (Pangolin — доступ к
сервисам, Remnawave — VPN, Komodo — управление серверами) ставятся по
отдельным документам, когда они понадобятся:

- [docs/pangolin-wildcard.md](../docs/pangolin-wildcard.md) — Pangolin;
- [docs/remnawave.md](../docs/remnawave.md) — Remnawave и маскировка.

Они подключаются к готовым базам через общий адрес `10.66.0.99` (порт из
`/etc/db/apps.d/`) — слой БД уже ждёт.

## Если что-то пошло не так

- [V1/14-troubleshooting.md](14-troubleshooting.md) — все симптомы и лечение;

- автоприёмка скажет, какой именно пункт не прошёл.
