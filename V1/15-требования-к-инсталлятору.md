# 15 — Требования к автоматическому установщику

Обновлено: 2026-11-12. См. также: [04-развёртывание](04-развёртывание-с-нуля.md),
`docs/pangolin-wildcard.md`.

Проект станет общедоступным: реальные пользователи ставят систему скриптами и не будут
разбираться руками. **Правило: каждый урок эксплуатации превращается в автоматику
установщика.** Этот файл — сводный чек-лист «что инсталлятор обязан делать».

## A. Базовая система (S0–S3)

1. Проверять `systemd-detect-virt` = kvm/none (иначе AmneziaWG невозможен) — честно
   отказывать с объяснением на OpenVZ/LXC.
2. AmneziaWG 3.1 из PPA с проверкой отпечатка ключа; DKMS-сборка с ожиданием 5–15 мин.
3. HPK и `server.secret` — генерировать один раз на кластер, раскладывать на все ноды.
4. SSH: сначала подтвердить ключевой вход, потом закрывать пароль (урок прошлой ошибки!).
5. ufw по таблице портов; rate-limit 53/udp; fail2ban с ignoreip mesh.
6. UTC + NTP на всех нодах; hostname по alias.

## B. Сеть и Swarm (S4)

7. Меш полный N×N: пир добавляется на ВСЕ ноды в обе стороны; проверка handshakes.
8. Новые узлы — **менеджерами** (правило 2K+1); worker'ы не предлагать.
9. DOCKER-USER с DROP-последним; **белые списки по портам КОНТЕЙНЕРОВ** (после DNAT!).
10. `nodes.map` раскатывается на все ноды при каждом изменении состава.

## C. Слой БД (S5)

11. **`max_connections=200`** (не 20 — каскадный отказ при старте Pangolin).
12. Секреты БД генерируются на нодах (umask 077), в чат/логи не попадают.
13. mongo mem_limit 512M + wiredTiger 0.256; mongosh — только отдельным контейнером.
14. Прокси перезапускать `docker restart` (не USR1).
15. `db-guard.timer` на каждой ноде; фенсинг включён.
15а. **PG-настройки против деградации (урок 2026-11-16):** `mem_limit` контейнера PG — **512M**
     (200M дали cgroup OOM-kill postgres → crash-recovery → 57P03 у всех панелей);
     при создании базы — `ALTER DATABASE <app> SET jit = off` (JIT монстр-плана на слабой
     ноде: 10.7 с → 20 мс после отключения); после ручных массовых правок БД — `ANALYZE`.
16. Проверка на выходе: запись через VIP + `pg_stat_replication`/`rs.status()`.
16а. **Лимиты логов докера:** `daemon.json` → `"log-opts": {"max-size": "20m", "max-file": "3"}`
     (урок 2026-11-16: mongod нарастил json.log до 1.5 ГБ на ноду); на работающей системе —
     logrotate `size 200M copytruncate` на `/var/lib/docker/containers/*/*-json.log`.
16б. **db-guard не должен грузить систему:** тик 10 с (не 5), монго-проверки одним вызовом
     с кешем 15 с, голоса `docker node update` — при смене значения или раз в 20 с.
     Проверка: `uptime` на холостой ноде < 1–2.
17. **Ресурсные профили (V1/20):** `--size=auto|s|m|l` (auto — по RAM нод) и опциональность
     `--panel=install|connect:<url>`, `--mtproto=yes|no`, `--komodo=yes|no`, `--kuma=yes|no`.
     Профиль S (ноды 1 ГБ) обязан укладываться: панель вовне кластера, без mongo/Kuma.
18. **Лимиты памяти вшиты во все контейнеры:** `mem_limit` + `NODE_OPTIONS=--max-old-space-size`
     для Node.js (панель Remnawave из коробки ставит кучу 16 ГБ!); journald `SystemMaxUse=200M`.
19. **Проверка на выходе:** `docker stats --no-stream` укладывается в бюджет профиля (V1/20);
     на ноде 1 ГБ — нода переживает cgroup-OOM панели (валится контейнер, не сервер).

## D. Pangolin (S6) — самый гадкий раздел

17. DNS-записи ДО установки: `<base>` и `*.<base>` A ×3, NS `_acme-challenge`/`cname`/`site`.
18. Wildcard-домен: `prefer_wildcard_cert: true` + `cert_resolver: "letsencrypt"` в config.yml.
19. **`enable_acme_client` — строго на одной ноде** (конфликты выдач).
20. **`pangolin-wildcard-repair.sh <ip>` после каждого старта pangolin** + таймер/cron
    (плейсхолдер пересоздаётся синхронизацией).
21. traefik+gerbil пересоздаются ТОЛЬКО вместе.
22. `unhealthy-restart.sh` — cron каждую минуту (docker не чинит unhealthy сам).
23. `pg-rebuild-standby.sh` — положить на ноды как штатное лечение таймлайна.
24. HTTP-01 не предлагать при multi-A — только DNS-01.
25. Цели ресурсов создавать ТОЛЬКО полным набором HC-полей (не через UI-мастер!):
    `hcEnabled, hcPath '/', hcScheme, hcMode 'http', hcHostname, hcPort, hcInterval 5,
    hcUnhealthyInterval 30, hcTimeout 5, hcMethod 'GET', hcFollowRedirects` +
    backend `method: 'https'` для самоподписанных сервисов.
26. Любое изменение ресурсов → триггерить re-sync агентов (не требовать ручного рестарта).
27. `update-pangolin-ips.sh` — вызывать из ddns при смене IP (trusted-upstreams/base_endpoint).

## E. Служебное (S7–S8)

28. Komodo: Core как swarm-сервис (перелетает сам), periphery — systemd, ключ Core пинится
    drop-in'ом (стабильная личность при переездах).
29. Мониторинг: Kuma + внешние проверки всех ресурсов ПО ВСЕМ IP; алерты с готовыми
    командами действия («детект — автомат, действие — одна команда»).
30. Бэкапы по правилу «2 соседние ноды»; недельные+ — со сжатием; отчёты о свежести.

## F. Верификация и отчёт (S9)

31. Автопроверки из [04](04-развёртывание-с-нуля.md) — обязательный итоговый отчёт
    (зелёный/красный по пунктам), не «надеюсь, работает».
32. Тестовый ресурс создаётся и удаляется самим установщиком — как доказательство пути.
33. Идемпотентность: повторный запуск любой стадии не ломает сделанное.

## G. Процесс (мета-требования)

34. Каждый инцидент с продакшена → пункт сюда + в [14-troubleshooting](14-troubleshooting.md).
35. Установщик объясняет простым языком, что делает (владелец — строитель, не девопс).
36. Секреты проходят мимо глаз пользователя: генерация на нодах, одноразовые токены.

## Проверка установщика (приёмка)

На пустых VPS прогнать: 3 ноды (минимум) + 5 нод (масштаб) + «одна нода легла» +
«смена IP» + «восстановление из бэкапа» — все дриллы из [17-дриллы](17-дриллы.md)
должны пройти БЕЗ ручных вмешательств.
