**Полётное правило: слои не смешиваются.** Машинный трафик (меш, Swarm, БД) не ходит через
VPN-слой; люди не ходят по мешу; вход не зависит от вычислений; состояние не зависит от входа.

## Почему gerbil И traefik (оба в цепочке 443)?

**Gerbil владеет портом 443** (Pangolin v2, кластерный режим) — это сервер туннелей +
SNI-прокси. Но он **закрытая коробка**: его таблица маршрутов генерируется панелью Pangolin
из БД, он умеет только «SNI = ресурс → туннель» и «всё остальное → traefik».
**Traefik — единственный программируемый переключатель** в цепочке: он делает
HTTP-роутинг дашборда, ACME-сертификаты, редиректы, и принимает НАШИ правила
`mask_config.yml` (HostSNI(vpn-*) → Xray, HostSNI(tg) → mtproto).
Без traefik маскировка уехала бы на нестандартные порты (хуже маскировка), а дашборд
Pangolin потерял бы роутинг и сертификаты. Схема: gerbil = «кто принимает на 443»,
traefik = «куда дальше». В одиночной (не кластерной) установке v1 traefik действительно
был единственным входом — отсюда возможное недоразумение по опыту старых серверов.

## Как течёт запрос к сервису

1. Браузер: `app.321r.ru` → DNS (multi-A на все ноды) → любая нода :443.
2. traefik на ноде смотрит SNI (имя) → находит ресурс Pangolin.
3. gerbil определяет, к какой ноде кластера прицеплен туннель сайта (Newt/агент), и
   пересылает туда, если цель здорова (`hcHealth`).
4. Newt/агент на целевой стороне стучится в `ip:port` сервиса (localhost, mesh или домашняя сеть).
5. Сервис отвечает; при смерти ноды междумашины браузер сам перебирает следующий IP из multi-A.

Ловушки этого пути (404/503/000, health-check'и, сходимость маршрутов) —
[14-troubleshooting](14-troubleshooting.md) и [15-требования-к-инсталлятору](15-требования-к-инсталлятору.md).

## Сети и адреса

- **Меш wg0**: 10.66.0.0/24 (a=1, b=2, c=3…), порт 51821/udp, транспорт AmneziaWG 3.1.
- **VIP БД 10.66.0.99/32** назначен на wg0 КАЖДОЙ ноды: приложение ходит на `10.66.0.99:<порт>`
  локально, за ним haproxy → текущий первичный. Адрес не меняется никогда — смена первичного
  невидима приложениям.
- Публичные порты: 80/443/8443/2053/2087/2222 tcp, 53/51820/21820/51821 udp —
  таблицы и смысл: [03-факты](03-факты.md), [12-безопасность](12-безопасность.md).
- Доверенная зона — меш: `ufw allow from 10.66.0.0/24`, всё остальное — default deny +
  DOCKER-USER для контейнерных публикаций.

## Домены сервисов

Каждый публичный сервис = **ресурс Pangolin** (`app.321r.ru`) → сайт-агент (Newt или CLI) →
`ip:port` цели. Сами сервисы запускаются Swarm'ом с ingress-портом: сервис плавает между
нодами, домен этого не замечает. Подробно: [08-домены-и-сертификаты](08-домены-и-сертификаты.md).

## Служебный слой

- **Komodo** — панель серверов и стеков: Core как swarm-сервис (сам перелетает), periphery
  (systemd) на каждой ноде, БД — MongoDB RS. UI: `komodo.321r.ru`.
- **Мониторинг** — Uptime Kuma (swarm-стек) + внешние проверки + Telegram-алерты (фаза 8).
- **Бэкапы** — копии между своими VPS по мешу (без облачных хранилищ), правило «2 соседние»
  (фаза 8): [10-бэкапы](10-бэкапы.md).
- **Remnawave** — VPN для людей (фаза 9): панель на b, Xray-ноды на всех, Reality :2087.
