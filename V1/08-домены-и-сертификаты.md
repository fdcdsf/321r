# 08 — Домены, DNS и сертификаты

Обновлено: 2026-11-12. См. также: [03-факты](03-факты.md),
`docs/pangolin-wildcard.md` (полный рецепт), `docs/dns.md` (таблица записей).

## Схема DNS: один хаб

Простая идея: **правишь одну строку — весь сайт находит всё**.

- Живые записи (правит `ddns.sh` каждые 2 мин): `a`, `b`, `c` — A на свой IP;
  `dns.321r.ru` — A ×3 (хаб).
- Всё остальное — **CNAME → `dns.321r.ru`** (создаются один раз и никогда не правятся).
- Wildcard: `321r.ru` и `*.321r.ru` — A ×3 (все IP нод): ресурсы второго уровня
  (`nov.321r.ru`, `proxmox.321r.ru`) работают без новых DNS-записей.
- NS-делегирование в свою встроенную DNS Pangolin: `_acme-challenge.321r.ru`,
  `cname.321r.ru`, `site.321r.ru` → `dns.321r.ru`.

**При смене IP:** 0 ручных правок — ddns правит 6 записей, CNAME не трогаются вовсе.

## Два механизма сертификатов (не путать!)

| Механизм | Для чего | Как | Где настроен |
|---|---|---|---|
| **traefik + CF API** (DNS-01) | дашборд Pangolin и роутеры traefik | ACME-резолвер `letsencrypt` с `dnsChallenge.provider: cloudflare` | `traefik_config.yml` + `CLOUDFLARE_DNS_API_TOKEN` |
| **Встроенный ACME Pangolin** (`cert_mode: pangolin`) | сертификаты ресурсов (`*.321r.ru`) | DNS-01 через свою встроенную DNS (NS `_acme-challenge`) | `privateConfig.yml`, **ТОЛЬКО на одной ноде!** |

Имена должны совпадать: `cert_resolver: "letsencrypt"` в config.yml ↔ резолвер в traefik.

## Почему HTTP-01 не работает (важно!)

Let's Encrypt (multi-VA, с 2025) проверяет **все** A-записи имени. При multi-A (наш случай:
3 IP) challenge живёт только на ноде-заявителе, чужие отвечают 404 → отказ.
**Все сертификаты — только DNS-01.** Это же закрывает и wildcard `*.321r.ru`.

## Wildcard-домены второго уровня: три бага Pangolin v2.3.4

Симптом: ресурсы `nov.321r.ru` отвечают 404, сертификат — «TRAEFIK DEFAULT CERT».
Причина — не маршрутизация, а сломанная выдача сертификата:

1. **Двойная звёздочка**: `createOrder` добавляет `*.` к уже wildcard-домену →
   Let's Encrypt получает `*.*.321r.ru` и отказывает; строка навсегда в `failed`.
2. **Плейсхолдер** «Server IP Address» в `dnsRecords.value` → валидация домена никогда
   не проходит («Domain is not verified»).
3. **`failed` не сбрасывается**: повторная выдача блокируется; `pangctl clear-certificates`
   удаляет и ВАЛИДНЫЕ сертификаты — пользоваться с осторожностью.

### Лечение (автоматика!)

```bash
scripts/pangolin-wildcard-repair.sh <один из IP A-записей>
```

Скрипт идемпотентен, пишет через VIP, чинит все три бага. **Запускать после каждого
рестарта pangolin** (синхронизация при старте пересоздаёт плейсхолдер!) — на стенде стоит
cron раз в 30 минут. Правила: БД — только через VIP (на стендбай — «read-only transaction»);
**не рестартовать pangolin сразу после ручной правки БД**.

### Что для wildcard нужно в конфиге

- `config.yml` (одинаков на всех нодах): домен `<base>` с `prefer_wildcard_cert: true` и
  `cert_resolver: "letsencrypt"`; `disable_config_managed_domains: false`.
- `privateConfig.yml`: `cert_mode: "pangolin"`, `use_pangolin_dns: true`, NS-имена
  `dns.<base>` / `cname.<base>` / `site.<base>`; `enable_acme_client: true` — **только на
  одной ноде кластера**.
- `server.secret` — одинаковый на всех нодах.
- DNS заранее: A ×3 на `<base>` и `*.<base>`, NS на `_acme-challenge.<base>`.

Полный рецепт с ямпами — `docs/pangolin-wildcard.md`.

## Проверка сертификата (быстро)

```bash
echo | openssl s_client -connect <имя>:443 -servername <имя> 2>/dev/null \
  | openssl x509 -noout -subject -ext subjectAltName
# ожидание: DNS:<base>, DNS:*.<base>
```

Изменения вступают в силу не мгновенно: Let's Encrypt + кэш traefik — дать пару минут.

## Домены сервисов: как завести новый

1. Wildcard-режим (основной): ресурс `<name>.321r.ru` создаётся в панели/API —
   DNS-записи не нужны вообще.
2. CNAME-режим (запасной): CNAME `<name>` → `dns.321r.ru` + ресурс на этот поддомен.
3. Цель ресурса: сайт-агент (cluster-*/winwin) + `ip:port`; **health-check обязателен и
   полный** (иначе цель не маршрутизируется — см. [14](14-troubleshooting.md), маска «404»).

## Ловушки (уже наступили — не повторять)

- Два механизма сертификатов — не путать и не включать ACME-клиент на нескольких нодах.
- Не смешивать UI-домен и config-домен для одного `base_domain`.
- `pangctl clear-certificates` сносит все сертификаты, включая валидные.
- Коллизия TXT при одновременной выдаче с 3 нод — лечится повтором (перезапуск traefik);
  в штате сертификаты ресурсов выдаёт одна ACME-нода.
- traefik живёт в `network_mode: service:gerbil` — пересоздавать их ТОЛЬКО вместе:
  `docker compose up -d --force-recreate gerbil traefik`.
