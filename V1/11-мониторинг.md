## Три кольца наблюдения

1. **Внутреннее** (на нодах): cron-скрипты следят за собой сами —
   `unhealthy-restart.sh` (каждую минуту), `db-guard` (каждые 10 с), `pangolin-wildcard-repair.sh`.
   Это «иммунитет» — система чинится без человека.
2. **Собственный мониторинг** (Uptime Kuma на своих VPS): видит сервисы изнутри кластера.
3. **Внешнее** (из интернета, минимум с 2 точек): UptimeRobot (бесплатный) + **домашний
   сервер** как независимый наблюдатель из РФ. Внешнее кольцо ловит то, чего не видит
   внутреннее: блокировки, падение DNS, смерть всего кластера.

Аналогия: внутреннее — самочувствие, собственное — медкабинет в доме, внешнее — сосед,
которому вы сказали «если я три дня не выхожу — стучи».

## Что мониторить (готовый список)

| Проверка | Откуда | Интервал | Что ловит |
|---|---|---|---|
| `https://pangolin.321r.ru/` = 200 | внешний, с РФ и из-за рубежа | 1 мин | вход жив, сертификаты живы |
| `https://komodo.321r.ru/` = 200 | внешний | 5 мин | панель жива |
| Каждый ресурс `*.321r.ru` = 200 | внешний, **по каждому IP** (`--resolve`) | 5 мин | маршрутизация на каждой ноде |
| `dig dns.321r.ru` = 3 адреса | домашний сервер | 5 мин | DNS-хаб и ddns живы |
| Handshake меша (`wg show`) | с каждой ноды на остальные | 1 мин | линк РФ↔зарубеж |
| Диск >85%, RAM, load | с нод | 5 мин | деградация железа |
| Свежесть бэкапов <24 ч | бэкап-ноды | час | «бэкапы бэкапятся» |
| db-guard: «мой инстанс не отвечает» | journalctl | событие | здоровье БД |
| Статусы health-check целей Pangolin | API панели | 5 мин | туннели/цели |

## Алерты в Telegram

- Бот проекта (создаёт владелец, фаза 0) → личный чат.
- **Формат алерта — с готовым действием** (главное требование фазы 8):
  алерт о смерти ноды содержит команду замены (`cluster.sh replace ...`) — человек с
  телефона вставляет одну строку. Детект — автомат, действие — одна команда.
- Тишина = норма; алерты шлём только про «надо пошевелиться».

## Kuma: начальный набор мониторов

| Монитор | Тип | Примечание |
|---|---|---|
| dashboard-pangolin | HTTP(s) | https://pangolin.321r.ru/ |
| komodo | HTTP(s) | https://komodo.321r.ru/ |
| ресурсы (по списку) | HTTP(s) | каждый `*.321r.ru` |
| noda-a/b/c-ping | Ping | по mesh-адресам 10.66.0.x |
| disk-a/b/c | Docker/container health | диски и контейнеры |
| backup-freshness | Push (от cron бэкапов) | если push не пришёл за 24 ч — алерт |

Kuma живёт в Swarm (`role != state`): смерть ноды → перелетает; данные — SQLite-том
(переезд — с ограничением, для истории — внешний статус).

## Домашний сервер как наблюдатель (минимальный датчик)

```bash
# cron на домашнем сервере, каждые 5 мин:
dig +short dns.321r.ru | wc -l          # ожидание: 3
curl -sf --max-time 10 https://pangolin.321r.ru/ -o /dev/null || <телеграм-алерт>
```

Домашний сервер не в критическом пути — он только стучит в колокол.

## Проверка, что мониторинг жив (парадокс: кто следит за следящим?)

- Раз в месяц: намеренно сломать тестовый ресурс → убедиться, что алерт пришёл.
- Kuma: проверка «heartbeat» push-мониторов бэкапов.
- Внешний мониторинг имеет свой статус-дашборд — раз в месяц взгляд.
