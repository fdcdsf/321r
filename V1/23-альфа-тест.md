### Разбор №8: как устроен :443 (важно для понимания продукта)

- host:443 → **gerbil:8443 (SNI-прокси Pangolin)**, traefik живёт в том же netns и напрямую
  НЕ опубликован. SNI-прокси извлекает имя из ClientHello, спрашивает у Pangolin маршрут
  и отправляет трафик по мешу на нужную ноду; «локальные» имена ведёт на traefik (127.0.0.1:443).
- Хранилище сертификатов traefik работает безупречно: на :2053 (вход dashboard, мимо gerbil)
  `SNI komodo.nakyi.ru → CN=komodo.nakyi.ru` ✓. Пара ключ/сертификат совпадает, формат файла
  идентичен панельному.
- На :443 рукопожатие для `komodo.nakyi.ru` обслуживается **не traefik**: в логах traefik нет
  ни одного следа (ни «Serving default certificate», ни выбора сертификата), ответ — Go-шный
  `404 page not found` и сертификат `CN=TRAEFIK DEFAULT CERT`. То есть gerbil-маршрутизация
  для ресурсного домена не находит цель и отвечает сама.
- Вывод: маршрут komodo-local.yml в traefik нужен и достаточен для трафика, дошедшего до
  traefik, но путь «клиент → :443 → gerbil» требует, чтобы Pangolin отдавал gerbil маршрут
  на ресурс. Следующий шаг: как gerbil получает список ресурсов (`--remoteConfig`) и почему
  komodo в него не попал (кэш/перезапуск/поле ресурса).
