# 05 — Добавление ноды (новый сервер в кластер)

Обновлено: 2026-11-12. См. также: [06-удаление](06-удаление-ноды.md),
[04-развёртывание](04-развёртывание-с-нуля.md), [03-факты](03-факты.md).

Кластер принимает новые сервера свободно: **N ≥ 3, «пока буквы алфавита не кончатся»**.
Новая нода = профиль в инвентаре, а не переделка системы.

## Правила перед добавлением

1. **Новая нода вступает МЕНЕДЖЕРОМ Swarm** (правило 2K+1: пережить K потерь — менеджеров
   ≥ 2K+1). Worker'ы не брать: db-guard на worker'е глухнет (нужен менеджер для меток).
2. Виртуализация — **KVM/полная VM**: на OpenVZ/LXC не встанет AmneziaWG (модуль ядра).
3. Минимум 3 узла в кластере остаётся всегда; железо подбирается под роль
   (`role=state/work/bulk` — см. [02-архитектура](02-архитектура.md)).
4. Данные нового узла — только вторые копии (правило «нет единственных копий»).

## Одной командой (проект, фаза 10)

```bash
# с рабочей машины (кластер уже живой):
bash cluster.sh join inventory.yaml --node d
```

## Пошагово (ручной путь, проверенный на стенде)

### Шаг 0 — инвентарь и DNS (5 минут)

1. Выбрать alias (`d`), mesh-IP (`10.66.0.4`), публичный IP сервера.
2. Внести строку в `nodes.map` (позже раскатается на все ноды).
3. DNS: создать A-запись `d.321r.ru` → IP; **добавить 4-ю строку в хаб** `dns.321r.ru`
   (A на тот же IP). CNAME'ы трогать не нужно.
   `ddns.sh` на новой ноде начнёт поддерживать обе записи сама.

### Шаг 1 — чистая VPS → базовый узел

S0–S2 из [04](04-развёртывание-с-нуля.md): ОС, пакеты, UTC, SSH 2222+ключи
(сначала подтвердить ключевой вход, потом закрывать пароль!), ufw-таблица
[03-фактов](03-факты.md), fail2ban, ddns.sh + cron.

### Шаг 2 — меш

1. AmneziaWG по рецепту `docs/amnezia-wg.md` (PPA, DKMS, 5–15 минут сборки).
2. `wg0.conf` новой ноды: свой адрес/ключ, пиры на все существующие ноды.
3. **На ВСЕХ старых нодах дописать пир к новой ноде** (меш полный N×N!) —
   иначе старые её не увидят.
4. **HPK (HeaderProtectionKey) — общий секрет кластера**: новый узел берёт значение
   из `/etc/amnezia/amneziawg/wg0.conf` любой старой ноды.
5. Поднять: `awg0-up` + `reresolve-dns.timer`; проверка: `wg show` — handshake со всеми,
   пинг 10.66.0.4.

### Шаг 3 — Swarm

```bash
# на новой ноде (токен — с любой менеджерской ноды: docker swarm join-token manager):
docker swarm join --token SWMTKN-... 10.66.0.2:2377
# метка роли (пример):
docker node update --label-add role=work <swarm-имя-новой>
```

Проверка: `docker node ls` — все Ready, включая новую. DOCKER-USER (`docker-user.sh` +
systemd) — поставить на новой ноде.

### Шаг 4 — слой БД

1. `db-prep.sh` на новой ноде (VIP, каталоги, ufw-зона контейнеров, nodes.map).
2. **`nodes.map` обновить на ВСЕХ нодах** (включая новую) — иначе цепь назначений и
   голоса не увидят узел.
3. Если новая нода нужна приложениям как реплика — расширить их `placement` в
   `/etc/db/apps.d/<app>.yaml` и запустить `db-add.sh <app>` (догонит узел сам:
   `pg_basebackup` / `rs.add`). Если нет — БД на новой ноде не заводятся (правило 9).
4. `db-guard.timer` — на новой ноде.

### Шаг 5 — Pangolin

1. Рендер `/opt/pangolin` из шаблонов (как на других нодах; `exit_node_name=<alias>`,
   `enable_acme_client` — НЕ включать, ACME-нода одна).
2. `docker compose up -d` → **`pangolin-wildcard-repair.sh <ip-новой>`** после старта!
3. Сайт-агент: `pangolin up site --id ... --secret ... --endpoint https://pangolin.321r.ru`
   (учётные данные — из панели, Sites → создать `cluster-<alias>`).
4. В панели/конфиге: `trusted-upstreams` дополнить IP новой ноды (делает
   `update-pangolin-ips.sh` — вызывается из ddns.sh).

### Шаг 6 — Komodo и служебное

1. Periphery: systemd-юнит как на других, onboarding-key в `/etc/db/secrets/`.
2. Мониторинг: добавить ноду в Kuma/внешние проверки; бэкапы — по правилу
   «2 соседние» ([10-бэкапы](10-бэкапы.md)).

### Шаг 7 — приёмка

Автопроверки S9 из [04](04-развёртывание-с-нуля.md) плюс:
`wg show` (все handshakes), `docker node ls`, тест ресурса `curl --resolve ... :443:<ip-новой>`
= 200, `journalctl -t db-guard` чист.

## Чек-лист «новая нода принята»

- [ ] A-запись `d.321r.ru` + строка в `dns.321r.ru` (ddns поддерживает)
- [ ] Меш: handshake со всеми N−1 узлами (и они — с ним!)
- [ ] Swarm: Ready, роль проставлена, менеджер (2K+1)
- [ ] `nodes.map` обновлён на всех нодах
- [ ] db-prep + db-guard; при необходимости db-add догнал S(X)
- [ ] Pangolin поднят, repair выполнен, сайт-агент `cluster-d` онлайн
- [ ] Periphery Komodo онлайн, мониторинг/бэкапы видят ноду
- [ ] nmap с соседа = таблица портов [03-фактов](03-факты.md)

## Типичные ошибки при добавлении

| Ошибка | Последствие | Как избежать |
|---|---|---|
| Забыли пир на старых нодах | новые↔старые не видят друг друга | шаг 2.3, проверка `wg show` |
| Не тот HPK | обфускация не совпадает — линк молчит | брать HPK из существующей ноды |
| Вступили worker'ом | db-guard не работает, метки не двигаются | всегда менеджер (2K+1) |
| Не обновили nodes.map на всех | цепь назначений ходит мимо, голоса неполные | шаг 4.2 |
| Забыли `pangolin-wildcard-repair.sh` | ресурсы 404 (баги v2.3.4) | шаг 5.2 + cron |
| Не дописали trusted-upstreams | часть трафика режется | `update-pangolin-ips.sh` |
