# 09 — Базы данных: слой БД

Обновлено: 2026-11-12. См. также: [03-факты](03-факты.md), [14](14-troubleshooting.md).
Полные детали — PLAN.md §4 и `docs/drills.md` (дриллы промоушена/фенсинга).

## Модель одной картинкой

- **Один инстанс = одно приложение** (D1). БД приложения X живут ТОЛЬКО на узлах S(X)
  из `/etc/db/apps.d/<app>.yaml`. Чужих баз на чужих дисках нет.
- **Адрес приложения — вечно статичный**: `10.66.0.99:<порт>` (VIP на каждой ноде).
  За VIP — локальный haproxy → текущий первичный. Приложение никогда не перепривязывается,
  смена первичного невидима.
- **Кто первичный — решает db-guard** (systemd-таймер ~10 с на каждой ноде), не движок:
  healthcheck → голоса менеджеров ≥2/3 → кворум Swarm → цепь S(X) → команда движку.
- PG: streaming primary/standby, promote через `pg_ctl promote`.
- Mongo: реплика-сет, но назначение наше (priority 1 назначенному, 0 остальным).
- **Фенсинг**: нет кворума Swarm >60 с → DROP в DOCKER-USER — изолированная нода молчит,
  данные целы; большинство пишет (CP-выбор, осознанный).

## Как добавить приложению базу

1. Запись в `/etc/db/apps.d/<app>.yaml`: имя, движок (`pg`/`mongo`), placement (список S(X)),
   класс (кластерный/локальный/служебный), арбитр (для Mongo |S|=2). Секретов в записи нет.
2. `bash /root/db-add.sh <app>` (с менеджерской ноды) — само:
   initdb + база/пользователь на первичном (пароль генерируется на ноде в
   `/etc/db/secrets/<app>.env`, umask 077) → `pg_basebackup` стендбайам / `rs.initiate`
   для Mongo → порт, прокси, метки `svc.<app>` и `db-primary-<app>`.
3. Проверка: запись через VIP работает; `pg_stat_replication` показывает стендбай(ы).

## Правила (нарушали — платили)

| Правило | Почему |
|---|---|
| Писать в БД **только через VIP** (10.66.0.99) | на стендбай — `read-only transaction`; записи мимо VIP расходятся с реальностью |
| `max_connections=200` (не 20!) | три пула Pangolin душат 20 слотов → каскадный отказ (урок ребут-теста) |
| mongosh — **только отдельным контейнером** `docker run --rm --network host mongo:7 mongosh ...` | `docker exec` внутрь mongod убивал базу по OOM (инцидент 2026-11-10) |
| Прокси перезагружать `docker restart` | `docker kill -s USR1` для Docker = «остановлен» |
| Возврат старого первичного = **пересборка basebackup** (~1 мин) | журнал уезжает вперёд точки раскола; это штатно |
| Стендбай с расхождением таймлайна → `pg-rebuild-standby.sh` | «requested timeline N is not a child» — штатное лечение, не авария |
| Миграции БД — одной задачей | параллельный DDL с разных нод мешает сам себе |
| RAM-капы обязательны | PG shared_buffers 16–32M, Mongo wiredTiger 0.256 + mem_limit 512M; резерв под движки ≤15–20% RAM ноды |
| **mem_limit PG = 512M** (не 200M!) | урок 2026-11-16: cgroup OOM-киллер убил postgres-бэкенд при лимите 200M → crash-recovery → 57P03 у всех панелей. `docker update --memory 512m` применён к pg-pangolin на всех нодах |
| **JIT в наших БД — выключен** | `ALTER DATABASE <app> SET jit = off` (вшито в db-add). JIT монстр-плана на слабой ноде давал 10.7 с вместо 20 мс → таймауты 57014 и пустые списки UI |
| **`ANALYZE` после крупных правок БД руками** | битая статистика (план думал «1 трлн строк» на таблицах из единиц) приводит к чудовищным планам |
| **Проверки не должны порождать жор** (урок 2026-11-16) | `mongosh` — это Node.js со стартом ~1–2 с CPU: db-guard запускал его каждые 5 с → load 4–5 на 1-ядерных нодах. Лечение: один вызов на тик + кеш 15 с, `docker node update` (голоса) — при смене значения или раз в 20 с, тик db-guard 10 с вместо 5 с |
| **Логи докера ограничены** | `mongod-komodo` нарастил json.log до 1.2–1.6 ГБ на ноде (rs.status-чекер каждые 5 с пишет строки). logrotate `size 200M copytruncate` на всех нодах + лимиты в daemon.json для свежих установок |

## db-guard: что он делает и где смотреть

Каждые ~5 с для инстансов своей ноды: healthcheck → «я в кворуме Swarm?» → голоса →
промоушен/назначение → перевешивание прокси → шаг назад старого первичного → фенс при
потере кворума. Штатно молчит.

```bash
journalctl -t db-guard -n 30 --no-pager
# маркеры: ПРОМОУШЕН, метка перехвачена, СТАРЫЙ ПЕРВИЧНЫЙ, апстрим прокси →,
#          ФЕНС / ФЕНС снят, стендбай перевешан, мой инстанс не отвечает
```

## Полезные команды

```bash
# кто первичный (PG):
docker exec -u postgres pg-<app> psql -U postgres -tAc "SELECT pg_is_in_recovery()"
# реплики:
docker exec -u postgres pg-<app> psql -U postgres -tAc \
  "SELECT application_name, client_addr, state FROM pg_stat_replication"
# запись через VIP:
. /etc/db/secrets/<app>.env
docker exec -e PGPASSWORD="$POSTGRES_PASSWORD" pg-<app> psql -h 10.66.0.99 -p 5432 -U postgres
# Mongo RS:
docker run --rm --network host mongo:7 mongosh "mongodb://10.66.0.99:27017/?replicaSet=rs_komodo" --quiet --eval 'rs.status().members.map(m=>m.name+":"+m.stateStr)'
# метки Swarm:
docker node inspect <swarm-имя> --format '{{json .Spec.Labels}}'
```
