## Как подключить устройство прямо сейчас

1. Страница подписок (красивая, с QR и кнопками клиентов):
   **`https://sub.321r.ru/N_fhWrr4aEaQ97EK`** (пользователь `testik`) — открыть в браузере
   или вставить в Hiddify/v2rayNG («Добавить подписку»). Там 3 сервера × 2 канала:
   маскировка :443 и Reality :2087.
2. Сырой URL для клиентов (base64): `https://rem.321r.ru/api/sub/N_fhWrr4aEaQ97EK`.
3. Панель: `https://rem.321r.ru` (логин `admin`; пароль в `/etc/db/secrets/remnawave-panel.env`
   на b — сменить + включить 2FA). Своего пользователя: Users → + (username + срок) →
   сквад `321r` → ссылка `https://sub.321r.ru/<shortUuid>`.
4. Корень `sub.321r.ru` намеренно «молчит» (502) — страница живёт только на путях
   `/<shortUuid>`, это защита от проверяющих.
5. **Telegram-прокси готов**: `tg://proxy?server=tg.321r.ru&port=443&secret=...`
   (секрет — `sudo mtbuddy links` на любой ноде; он один на кластер, работает на всех
   трёх нодах). Проверьте в Telegram на телефоне. Маска: `https://tg.321r.ru/` выглядит
   обычным сайтом. Звонки Telegram через прокси не идут — это ограничение MTProto-прокси.

## Идея маскировки (из прошлого сервера xdom45 — адаптировано)

Порт 443 каждой ноды выглядит для проверяющего как **обычный сайт с настоящим сертификатом**,
но пропускает «своих»: VPN-клиент с ключом попадает в туннель, Telegram-клиент с секретом —
в прокси, а случайный гость видит обычную страницу-заглушку.

```
SNI vpn-a.321r.ru  → gerbil → traefik (passthrough) → Xray :9446 → VLESS | заглушка :9447
SNI tg.321r.ru     → gerbil → traefik (passthrough) → mtproto :8446 → Telegram | заглушка :8448
SNI rem.321r.ru    → gerbil → traefik → панель Remnawave (ресурс Pangolin)
```

## Домены и порты

| Домен | Что | Порт за маской |
|---|---|---|
| `vpn-a / vpn-b / vpn-c.321r.ru` | VPN-нода (VLESS+TLS+fallback) | 9446 → заглушка 9447 |
| `tg.321r.ru` | Telegram-прокси (mtproto.zig) | 8446 → заглушка 8448 |
| `rem.321r.ru` | панель Remnawave | 127.0.0.1:3000 (на b) |
| `vpn-*.321r.ru:2087` | Reality (запасной VPN-канал) | 2087 |

⚠️ Маска Telegram — `tg.321r.ru`, НЕ apex `321r.ru`: `_acme-challenge.321r.ru` делегирован
нашей Pangolin-DNS, certbot через Cloudflare для apex не пройдёт. Порт 2053 занят запасным
дашбордом Pangolin — Reality живёт на 2087 (правка плана).

## Панель Remnawave (два режима — выбор при установке!)

- **Режим B (наш, основной):** панель на серверах (compose на b), БД — **наш слой БД**
  (`apps.d/remnawave.yaml`: PG кластерный [b,c] — standby на c, VIP 10.66.0.99:5433).
  Люди заходят на `rem.321r.ru` (ресурс Pangolin с полным HC), агенты-ноды ходят к панели
  по сети. Смерть b: VPN живёт по кешу, панель поднимается на c за минуты (БД уже там).
- **Режим A (как раньше):** панель на домашнем сервере за туннелем Pangolin (сайт winwin);
  ноды подключаются к `rem.321r.ru` по обычному HTTPS. Ничего не ставим — только регистрируем ноды.

## Что где лежит (секреты — только на серверах!)

| Что | Где |
|---|---|
| БД-пароль панели | `/etc/db/secrets/remnawave.env` (генерирует db-add) |
| Секреты панели + админ + API-токен | `/etc/db/secrets/remnawave-panel.env` (b) |
| Сертификаты маскировки | `/etc/letsencrypt/live/mask/` (симлинк; certbot, автопродление) |
| Конфиги нод (compose) | `/opt/remnanode/` на a/b/c |
| Панель (compose, .env) | `/opt/remnawave/` на b |

Админ панели: логин `admin`; пароль — в `remnawave-panel.env` (**сменить + включить 2FA**).

## Подключение устройств (для владельца)

1. Открыть `https://rem.321r.ru` → войти.
2. Users → создать пользователя → получить ссылку подписки (URL вида `rem.321r.ru/api/sub/...`).
3. Подписка отдаёт конфиги: VLESS+TLS на `vpn-a/b/c.321r.ru:443` (маскировка под сайт) и
   запасной Reality на :2087. Клиенты: Hiddify, v2rayNG, Streisand и т.п.
4. Telegram-прокси (когда готов): `tg://proxy?server=tg.321r.ru&port=443&secret=...`

## Автоустановщик (как это войдёт в скрипты)

Модуль S8-VPN с выборами: `--panel=install|connect:<url>`, `--mtproto=yes|no`. Этапы:
certbot-серты per node → nginx-заглушки → (install: apps.d + db-add + compose панели +
ресурс Pangolin) → ноды в панели + remnanode compose → passthrough в `mask_config.yml`
(отдельный файл — Pangolin не затирает!) → ufw (2087, 9446/8446 от docker-подсети) →
mtproto + egress-обход для РФ-ноды → автопроверки. Требования —
[15-требования-к-инсталлятору](15-требования-к-инсталлятору.md).

## Тонкости (уже наступили)

- API панели: JWT — только с заголовком `X-Remnawave-Client-Type: browser`; автоматизация —
  API-токен (`scopes: ["*"]`); API зовётся через `https://rem.321r.ru` (панель убивает
  прямые сокеты без HTTPS-заголовков прокси).
- Metrics-порт панели перенесён на 3002: 3001 на всех нодах занят Uptime Kuma.
- Пароль админа ≥24 символов + спецсимволы.
- Egress к Telegram: из РФ (нода a) IP Telegram блокируются — mtproto на a ходит наружу
  через mesh-шлюз на b; b/c — напрямую.
- `nginx reload` ненадёжен — везде `systemctl restart nginx` (урок xdom45).
