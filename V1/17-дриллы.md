# 17 — Дриллы (учения)

Обновлено: 2026-11-12. См. также: [13-эксплуатация](13-эксплуатация-и-отказы.md).
Протоколы прошедших дриллов — `docs/drills.md` (эталонный формат).

## Зачем

Система обещает «пережить потерю ноды и месяц без присмотра». **Дрилл — это чек, который
превращает обещание в факт.** Непроверенная отказоустойчивость — сказка.

## Правила проведения (закреплены инцидентами)

1. **Дрилл-блок — одним куском из одного терминала**; первая строка проверяет ноду-жертву
   (урок 2026-11-10: `docker stop` ушёл не на ту ноду).
2. Останавливать docker — **`systemctl stop docker docker.socket`** (иначе socket оживляет).
3. mongosh руками — только отдельным контейнером.
4. Перед дриллом: git commit, свежие бэкапы, рабочее окно (не 3 часа ночи в РФ-пик).
5. После дрилла: протокол в `docs/drills.md` (дата, что делали, метрики, находки) +
   находки → вики + инсталлятор.

## Каталог дриллов

| Дрилл | Что имитируем | Цель/метрика | Период |
|---|---|---|---|
| **Смена IP** (синтетическая) | провайдер сменил IP | ddns ≤2 мин, reresolve ≤45 с, кластер жив | ежеквартально |
| **Промоушен PG** | смерть первичного PG | следующий по цепи за ≤2 мин (на стенде: 39 с, после оптимизации db-guard — ~10 с), прокси/метки корректны | ежеквартально |
| **Назначение Mongo** | смерть primary mongod | назначение ≤1 мин (на стенде: 24 с), Core пишет через VIP | ежеквартально |
| **Фенсинг** | изоляция ноды (потеря кворума) | фенс ≤60 с (57 с), большинство пишет, возврат без потерь | ежеквартально |
| **Слабая нода** | на ноде мало RAM | нет чужих инстансов, память в норме | при смене ролей |
| **«Нода ложится»** (стоп docker) | падение ноды с сервисами | Swarm переносит задачи (Core, Kuma), без фенса | ежеквартально |
| **«VPS-2 лёжит»** (панель Remnawave) | потеря панели VPN | маски 200, Xray жив, панель 503, возврат ~30 с (2026-11-16) | ежеквартально |
| **«IP заблокирован»** (РКН режет ноду) | блокировка IP | клиенты multi-A идут на 2 живые ноды (2026-11-16; блокировать по контейнерным портам!) | ежеквартально |
| **«Панель под капом падает»** (cgroup-OOM) | смерть панели | ingress не страдает, панель ~5 с (2026-11-16) | ежеквартально |
| **Ребут-тест** (все серверы) | полное отключение стойки | самоизлечение всего за ≤10 мин | раз в полгода |
| **Блокировка IP** (uffw-drop на 443/53) | РКН | вход из РФ через другие IP | ежеквартально |
| **Дрилл данных** | смерть первичного PG Pangolin | db-guard ≤2 мин, дашборд пишет дальше | ежеквартально |
| **Восстановление из бэкапа** | «ракета в датацентр» | новый кластер + данные из копий (RTO часы) | ежеквартально |

## Формат протокола (шаблон для docs/drills.md)

```markdown
## Дрилл <название> (<дата>): <ПРОЙДЕН/НЕ ПРОЙДЕН>
**Цель:** ...  **Что делали:** (блоки команд с указанием нод)  **Метрики:** ...
**Находки:** (что вскрыли)  **Что автоматизировать/исправить:** ...
```

## Что дриллы уже доказали (стенд, 2026-11)

- Промоушен PG 39 с; назначение Mongo 24 с; фенсинг 57 с / снятие 44 с.
- «Нода ложится»: Core и Kuma перелетают сами, сервисы не замечают.
- Смена IP: ddns сам чинит на первом тике cron, меш переподключается через reresolve.
- Ребут-тест (все 3 сервера): Swarm/БД/Komodo/сертификаты восстановились сами; вскрыты и
  исправлены max_connections, unhealthy-restart, пересборка стендбая (всё в автоматике).
- Слабая нода (a, 2 GB): чужих баз нет, память в норме.

## Дриллы фазы 5 (в очереди)

1. «Нода ложится» — для туннелей Pangolin: Newt уходит на живую ноду (секунды).
2. «Нода заблокирована» — ресурсы открываются через остальные IP.
3. «Данные пережили» — смерть первичного PG при живом дашборде.

## Календарь (итог)

- Ежеквартально: полный набор + восстановление из бэкапа.
- Раз в полгода: ребут-тест всего стойла.
- После каждого изменения архитектуры: точечный дрилл затронутой подсистемы.
