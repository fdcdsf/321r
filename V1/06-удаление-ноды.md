# 06 — Удаление ноды (сужение кластера)

Обновлено: 2026-11-12. См. также: [05-добавление](05-добавление-ноды.md),
[07-замена-сервера](07-замена-сервера.md).

Убрать сервер можно **в любой момент и без потерь данных** — это гарантирует правило
«нет единственных копий на ненадёжных ящиках» ([01-обзор](01-обзор-проекта.md), п.3).

## Когда убираем ноду

- Кончилась бесплатная аренда (случай D/E).
- Сервер стал плохим (диск, сеть) — лучше заменить: [07-замена](07-замена-сервера.md).
- Кластер сужается с 5 до 3.

**Минимум в кластере — 3 узла** (кворум Swarm 2/3, голоса db-guard ≥2/3). И проверка
2K+1: если планируется жить с K возможными потерями — менеджеров должно остаться ≥ 2K+1.

## Порядок (одной командой: `cluster.sh leave --node e`)

### Шаг 1 — проверить, что на ноде нет единственных копий

```bash
# на любой ноде: где какие БД живут
cat /etc/db/apps.d/*.yaml          # placement каждого приложения
docker node inspect <swarm-имя> --format '{{json .Spec.Labels}}'
```

- Если убираемая нода входит в S(X) какого-то приложения — **сначала сузить placement**
  (убрать узел из `apps.d/<app>.yaml`) и пересоздать реплики: `db-add.sh <app>`
  (оставшиеся узлы пересоберутся между собой; для Mongo — `rs.remove`).
- Если на ноде первичный БД — db-guard назначит нового по цепи сам (≤2 мин),
  но лучше подстраховаться и подождать переключения.
- Компактное правило: **на уходящей ноде не должно остаться ни одной базы**.

### Шаг 2 — Swarm: drain → remove

```bash
docker node update --availability drain <swarm-имя>   # задачи Swarm переехали
docker node rm --force <swarm-имя>                    # (сначала обычный rm, --force если мертва)
```

Проверка: `docker node ls` — узла нет; сервисы (Core, Kuma) работают на выживших.

### Шаг 3 — вычистить узел из кластера (ОБЯЗАТЕЛЬНЫЙ хвост!)

1. **`nodes.map` на всех оставшихся нодах**: удалить строку узла.
   *Забыли — цепь назначений db-guard будет ходить через мёртвый узел (задержки/ошибки).*
2. **`apps.d/`**: placement уже сузили в шаге 1 — сверить, что узла нигде нет.
3. **Pangolin**: удалить сайт-агент `cluster-<alias>` (панель → Sites) и его токены;
   убрать IP ноды из `trusted-upstreams` (или `update-pangolin-ips.sh` пересчитает).
4. **DNS**: удалить A-запись `<alias>.321r.ru` и её строку в хабе `dns.321r.ru`.
   Wildcard/CNAME не трогать.
5. Мониторинг: снять ноду с проверок; бэкапы: убрать из цепочки (проверить, что правило
   «2 соседние» всё ещё выполняется для оставшихся).
6. Компоненты меша: удалить пир уходящей ноды из `wg0.conf` живых нод (опционально,
   они просто молчат; но чистота — хорошо).

### Шаг 4 — финальная проверка

```bash
docker node ls                          # N−1 Ready, кворум есть
wg show                                 # handshakes только между живыми
curl -sk https://pangolin.321r.ru/ -o /dev/null -w '%{http_code}\n'   # 200
journalctl -t db-guard -n 20            # без «не отвечает»/ошибок цепи
```

И пересчитать кворумы: менеджеров ≥ 2K+1 для ожидаемого K.

## Чек-лист «нода убрана»

- [ ] Нет баз с единственными копиями (placement сузили, rs.remove/basebackup выполнены)
- [ ] drain → rm: `docker node ls` чистый, сервисы переехали
- [ ] nodes.map вычищен на всех нодах ★ (самый частый забытый шаг!)
- [ ] apps.d не ссылается на узел
- [ ] Pangolin: агент удалён, trusted-upstreams обновлён
- [ ] DNS: записи узла удалены
- [ ] Мониторинг/бэкапы обновлены; «2 соседние» выполняется
- [ ] Кворумы пересчитаны (2K+1)

## Если нода «сама ушла» (мертва физически)

То же самое, но drain не нужен — сразу `docker node rm --force`, дальше шаги 3–4.
Если это была потеря, а не плановое сужение — действовать по
[07-замена-сервера](07-замена-сервера.md).
