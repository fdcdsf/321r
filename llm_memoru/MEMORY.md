## 1. Рабочий режим (нарушать нельзя)

1. **Модель готовит команды, пользователь вставляет и присылает вывод.** Полная вставка —
   только для исходников файлов, которые идут в git (их модель пишет сама, файлами).
2. **Секреты — никогда в чат и никогда в git:** age-ключ, CF-токен, HPK, SSH-ключи, пароли.
   Пароли генерируются НА НОДАХ в файлы `umask 077` (`/etc/db/secrets/<app>.env`, chmod 600).
   Файл `C:\Users\user\AppData\Roaming\sops\age\keys.txt` — не печатать даже частично.
3. **Доставка на ноды — SFTP** (репозиторий приватный, ноды pull не умеют). Скрипты — в git,
   на ноды через SFTP + `scp -P 2222` между нодами по mesh.
4. **Крупные вставки — кусками ~50 строк** с проверками `wc -l` / `bash -n` / md5.
5. **Патчи и мок-тесты — локально ДО выкладки.** Харнесс `tests/run_db_guard.sh` (71/71) доказывает
   логику, но НЕ семантику docker CLI — флаги проверять по живому `--help` (урок бага №1 ниже).
6. Вывод пользователя иногда обрезается — при сомнениях переспрашивать свежей командой.
7. Объяснения — по-русски, простым языком, с аналогиями. Скорость важнее церемоний, но
   порядок шагов PLAN — контракт.

## 3. Архитектура БД (v14 — суть)

- **PG/Mongo — «глупые исполнители» воли Swarm.** БД(X) живёт ТОЛЬКО на узлах S(X) из
  `apps.d/<app>.yaml`; placement БД = S(X) точно; per-node сервисы свои БД не реплицируют.
- **DCS = Docker Swarm** (метки `db-primary-<app>`, Raft, placement). Этим заняты голоса
  `vote.<app>.<alias>=<0|1>-<epoch>` (свежесть 45 с), кворум ⌊M/2⌋+1, цепь S(X) a→b→c.
- **Адрес для приложения — вечно статичный:** `10.66.0.99:<порт>`. За ним локальный haproxy на
  каждой ноде → текущий первичный. Приложение никогда не перепривязывается.
- **PG:** async streaming primary/standby (один инстанс = одно приложение); promote через
  `pg_ctl promote`; старый первичный шагает назад (standby.signal). **Mongo:** RS, но первичный
  назначается скриптом (priority 1 назначенному, 0 остальным; force-reconfig без первичного).
- **db-guard** (systemd-timer 5 с на каждой ноде, `/usr/local/bin/db-guard.sh`):
  healthcheck TCP → голоса → кворум → promote + claim метки + перевешивание прокси →
  шаг назад старого первичного → **фенс: нет кворума >60 с → 3 DROP в DOCKER-USER (позиция 1)**.
  Нет кворума → выйти до решений (CP). Метка `db-primary-<app>` живёт ТОЛЬКО на узле первичного.
- Классы: кластерный (|S|≥2) / локальный / служебный (арбитры). Mongo |S|=2 → арбитр на 3-м узле.
- Новое приложение: запись в `apps.d/` + `scripts/db-add.sh` — само (basebackup/-R, RS, метки, proxy).

## 6. Памятка команд (быстрая)

- Логи db-guard: `journalctl -t db-guard -n 30 --no-pager`; маркеры: `ПРОМОУШЕН`,
  `метка перехвачена`, `СТАРЫЙ ПЕРВИЧНЫЙ`, `шаг назад отложен`, `апстрим прокси →`,
  `ФЕНС`/`ФЕНС снят`, `стендбай перевешан`, `мой инстанс не отвечает`.
- PG: `docker exec -u postgres pg-<app> psql -U postgres -tAc "SELECT pg_is_in_recovery()"`;
  реплики: `... -c "SELECT application_name, client_addr, state FROM pg_stat_replication"`;
  цель стендбая: `... SHOW primary_conninfo | grep -o 'host=[0-9.]*'` (без пароля в выводе!).
- Запись через VIP: `. /etc/db/secrets/<app>.env` + `docker exec -e PGPASSWORD="$POSTGRES_PASSWORD"
  pg-<app> psql -h 10.66.0.99 -p 5432 -U postgres`.
- Метки: `docker node inspect <swarm-имя> --format '{{json .Spec.Labels}}'`.
- Тесты: git-bash → `bash tests/run_db_guard.sh` (итог `PASS=61 FAIL=0`).
- Mongo/проверки RS: **только отдельным контейнером** —
  `docker run --rm --network host mongo:7 mongosh "mongodb://10.66.0.99:27017/?replicaSet=rs_komodo" --quiet --eval '...'`.
  НЕ `docker exec mongod-... mongosh` руками: mongosh внутри контейнера по OOM убил mongod
  (инцидент 2026-11-10; db-guard своим мелким myState можно, руками — нельзя).
- DOCKER-USER фенс — позиция 1; `scripts/docker-user.sh` при перезапуске СТИРАЕТ правила фенса.
- curl exit: 0=open, 28=timeout, 7=refused.
