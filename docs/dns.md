## Принцип: один хаб

- **`a` / `b` / `c`** — A-записи, обновляются **ddns.sh автоматически** (каждая нода — свою).
  Это единственные «живые» записи.
- **`dns.321r.ru`** — A ×3 (те же IP): хаб для остальных + адрес DNS-сервера кластера.
  Тоже обновляется ddns.sh (каждая нода — свою строку).
- **Всё остальное — CNAME → `dns.321r.ru`.** Cloudflare разворачивает CNAME в 3 IP
  (multi-A сохраняется). Такие записи создаются **один раз и больше не редактируются**.

Итог при смене IP у провайдера: **0 ручных правок** — ddns.sh сама правит 6 записей
(свою `a` + свою строку в `dns`).

## Когда появятся узлы D и E

| Имя | Тип | Контент |
|---|---|---|
| `d` | A | `<IP-D>` (DDNS) |
| `e` | A | `<IP-E>` (DDNS) |
| `dns` | A | + `<IP-D>`, + `<IP-E>` (строки добавляет ddns.sh) |

CNAME'ы трогать не нужно — они смотрят на хаб.

## Проверка

```
nslookup a.321r.ru        # должен отдать 178.236.242.213
nslookup pangolin.321r.ru # три IP (развёрнутый CNAME), порядок не важен
```
